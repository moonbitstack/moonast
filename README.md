## What it does

A generator reads declarations you have already written, finds the annotations on them, and
writes the code those annotations ask for. moonast is the three pieces that make that possible,
one job each:

| Layer | Package | What it does |
|:--|:--|:--|
| Read | `moonast/gen` | Parses a file and gives every declaration as a plain view: `Struct`, `Enum`, `Func`. Types are kept as the source text that wrote them. |
| Write | `moonast/quote` | A template is real MoonBit with `$holes`. It is parsed, each hole is filled by replacing the node it stands for, and the official printer lays the result out. |
| Generate | `moonast/gen`, `moonast/cli` | `render` puts a header above the code; `run` is the whole `main` of a generator binary. |

Between them, `moonast/attr` turns an annotation's payload into typed arguments.

## A complete derive

The generator is written once, as a module of its own. A project that uses it writes one
declaration, one rule in `moon.mod`, and one line in `moon.pkg`.

### 1 · The declaration you annotate

<!-- nocheck -->

```moonbit
// models.mbt
#demo.describe
pub struct Point {
  x : Int
  y : Int
}
```

### 2 · The generator, written once

<!-- nocheck -->

```moonbit
// src/main.mbt — give every annotated struct a `describe` method
struct Describe {}

impl @gen.Generator for Describe with fn name(_) {
  "describe"
}

impl @gen.Generator for Describe with fn generate(_, decls) {
  let out = []
  for decl in decls {
    guard decl is Struct(name~, fields~, attrs~, ..) &&
      @attr.find(attrs, "demo.describe") is Some(_) else {
      continue
    }
    let text = name + "(" + fields.map(f => f.name).join(", ") + ")"
    let source =
      #|fn $T::describe(self : $T) -> String {
      #|  ignore(self)
      #|  $text
      #|}
    out.push(
      @quote.items(source)
      .set("T", @quote.ident(name))
      .set("text", @quote.string(text))
      .render(),
    )
  }
  @quote.join(out)
}

async fn main {
  @cli.run(Describe::{}, @env.args()[1:])
}
```

<!-- nocheck -->

```text
// moon.pkg of that package
import {
  "moonbitstack/moonast/quote",
  "moonbitstack/moonast/attr",
  "moonbitstack/moonast/gen",
  "moonbitstack/moonast/cli",
  "moonbitlang/async",
  "moonbitlang/core/env",
}
```

### 3 · The rules that keep it up to date

<!-- nocheck -->

```text
// moon.mod of the project that uses the generator
rule(name: "describe", command: "moonx <module>@<version> -C \"$mod_dir\" \"$input\" -o \"$output\"")
```

<!-- nocheck -->

```text
// moon.pkg of the package whose declarations it reads
dev_build(rule: "describe", input: "models.mbt", output: "describe.g.mbt")
formatter(ignore: [ "describe.g.mbt" ])
```

### 4 · The file it writes

Running `moon run . --target native -- models.mbt -o describe.g.mbt` writes:

<!-- nocheck -->

```moonbit
// Generated by describe from models.mbt. Edit those files, not this one.

///|
fn Point::describe(self : Point) -> String {
  ignore(self)
  "Point(x, y)"
}
```

From then on `moon check`, `moon build` and `moon run` regenerate it whenever `models.mbt`
changes.

## An annotation that takes arguments

`#demo.getters(skip=token)` gives every field a getter except the ones named. The payload is
read against a spec, so a missing or mistyped argument is refused with the annotation's line
and column instead of producing code:

<!-- nocheck -->

```moonbit
impl @gen.Generator for Getters with fn generate(_, decls) {
  let out = []
  for decl in decls {
    guard decl is Struct(name~, fields~, attrs~, ..) else { continue }
    guard @attr.find(attrs, "demo.getters") is Some(annotation) else { continue }
    let skip = @attr.Spec::new("demo.getters")
      .many("skip", Ident)
      .bind(annotation)
      .strs("skip")
    for f in fields {
      guard !skip.contains(f.name) else { continue }
      let source =
        #|fn $T::$field(self : $T) -> $Ty {
        #|  self.$field
        #|}
      out.push(
        @quote.items(source)
        .set("T", @quote.ident(name))
        .set("field", @quote.ident(f.name))
        .set("Ty", @quote.ty(f.ty).render())
        .render(),
      )
    }
  }
  @quote.join(out)
}
```

<!-- nocheck -->

```moonbit
#demo.getters(skip=token)
pub struct User {
  id : Int
  name : String
  token : String
}
```

<!-- nocheck -->

```moonbit
// Generated by getters from models.mbt. Edit those files, not this one.

///|
fn User::id(self : User) -> Int {
  self.id
}

///|
fn User::name(self : User) -> String {
  self.name
}
```

## A template on its own

No generator binary is needed to use a template. A package that builds code can fill one
directly:

<!-- nocheck -->

```moonbit
let source =
  #|fn $T::$field(self : $T) -> $Ty {
  #|  self.$field
  #|}
let code = @quote.items(source)
  .set("T", @quote.ident("User"))
  .set("field", @quote.ident("id"))
  .set("Ty", @quote.ty("Int").render())
  .render()
println(code)
```

## Interface

### `moonast/quote`

| Item | Takes | Gives |
|:--|:--|:--|
| `items(source)` | MoonBit declarations with holes | a `Template` |
| `expr(source)` | one expression with holes | a `Template` |
| `ty(source)` | one type with holes | a `Template` |
| `Template::set(hole, code)` | a hole's name, a `Code` | the template, filled |
| `Template::splice(hole, codes)` | a list hole's name, codes | the template, spliced |
| `Template::render()` | — | a `Code`, or `Refused` |
| `ident(name)` | a name, or `@pkg.name` | a `Code`, or `Refused` |
| `string(text)` | any text | a `Code` |
| `int(value)`, `bool(value)` | a literal | a `Code` |
| `join(codes)` | declaration codes | one `Code`, or `Refused` |
| `Code::items()` | — | the official syntax tree, when it is declarations |
| `Code::to_string()` | — | the source text |

### `moonast/attr`

| Item | Takes | Gives |
|:--|:--|:--|
| `name_of(attr)` | an annotation | its full name, `lib.name` |
| `find(attrs, name)` | annotations, a name | the first one called that |
| `all(attrs, name)` | annotations, a name | every one called that |
| `under(attrs, lib)` | annotations, a prefix | every one under `lib.` |
| `Spec::new(name)` | an annotation's name | a spec with no parameters |
| `Spec::positional(key, kind)` | required, by position or name | the spec |
| `Spec::required(key, kind)` | required, by name | the spec |
| `Spec::optional(key, kind)` | may be left out | the spec |
| `Spec::many(key, kind)` | may be given again | the spec |
| `Spec::bind(attr)` | an annotation | its arguments, or `Refused` |
| `Args::get`, `str`, `strs`, `bool`, `has` | a parameter's key | what was given for it |

`Kind` is `Str`, `Bool`, `Ident` or `Type`; each `Args` reader answers in the kind its spec
asked for.

### `moonast/gen`

| Item | Takes | Gives |
|:--|:--|:--|
| `read(file, source)` | a file name and its source | its declarations, or `Refused` |
| `render(generator, inputs)` | a generator and its inputs | the file to write |
| `Generator::name()` | — | the name in the header |
| `Generator::generate(decls)` | every declaration | the code to write |
| `Decl` | — | `Struct`, `Enum`, `Func` or `Other` |
| `Decl::attrs()`, `Decl::raw()` | — | the annotations on it, the syntax tree behind it |
| `Field`, `Param`, `Pass` | — | a struct field, a parameter, how it is passed |

### `moonast/cli`

| Item | Takes | Gives |
|:--|:--|:--|
| `run(generator, args)` | a generator, `[-C <dir>] <inputs...> -o <output> [--check]` | writes the file, or refuses when it is stale |

## Holes

| Hole | Takes | Written as | Gives |
|:--|:--|:--|:--|
| `$T` | a type or a constructor | `fn f(x : $T)` | `fn f(x : Int)` |
| `$name` | a value, an expression, or a name | `$value + 1` | `41 + 1` |
| `@pkg.$name` | a name inside a package | `app : @web.$T` | `app : @web.App` |
| `$name*` | a list of them | `[$items*]` | `[1, 2, 3]` |
| `$name` in a string | a name or a string, as text | `"field $key"` | `"field first name"` |
| `$$` | a literal dollar sign | `"$$5"` | `"$5"` |

A hole's case is part of the grammar: upper case where a type or constructor goes, lower case
where a value or a binder goes. A list hole expands among statements, array elements, and the
arguments of a function application.

## Annotation arguments

The parser reads strings, `true`/`false`, names and nested calls as annotation arguments. There
are no arrays and no numbers, a generic or qualified type has to be written as a string, and a
keyword cannot be a label. A list is written as a repeated key, `tags="a", tags="b"`, which
`Spec::many` accepts.

When a payload is outside that grammar, the annotation has no name as far as moonast is
concerned, so `find` does not see it.

## Refusals

Every fallible call gives a `Refused` with a message, and with a position where there is one to
give:

| From | Refused when |
|:--|:--|
| `quote` | the template is not MoonBit, a hole is left empty, a fill names no hole, or a fill does not fit where it stands |
| `attr` | the payload cannot be read, a required parameter is missing, one is unknown, mistyped, or given twice |
| `gen` | an input file is not MoonBit |
| `cli` | the command line is wrong, or `--check` found the output out of date |
