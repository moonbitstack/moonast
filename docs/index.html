Code generation for MoonBit

Write the annotation.
Fill the hole.
Keep the file.

moonast reads declarations you have already written, finds the annotations on them, and writes the code those annotations ask for. Templates are real MoonBit with $holes — parsed, filled and printed by the official parser, so quoting, escaping and layout come out the way moon fmt lays them out.

Three layers

Read a declaration. Write a template. Generate a file.

Each layer is one package, and each one is usable on its own. A generator is the three of them in sequence, plus a main that writes the file.

01 — moonast/gen

Read declarations

A file goes in, plain views come out: Struct, Enum, Func. Types are kept as the source text that wrote them, which is what a generator splices into new code.

let source = "pub struct Point {\n  x : Int\n  y : Int\n}"
guard @gen.read("models.mbt", source) is [Struct(name~, fields~, ..)] else {
  abort("a struct")
}
inspect(name, content="Point")
inspect(fields.map(f => f.name).join(", "), content="x, y")
02 — moonast/quote

Write templates

A template is MoonBit with $holes. It is parsed with the holes standing as placeholders, each fill is put where its placeholder stands, and the result is printed by the official formatter.

let source =
  #|fn $name() -> $T {
  #|  $value
  #|}
let code = @quote.items(source)
  .set("name", @quote.ident("answer"))
  .set("T", @quote.ident("Int"))
  .set("value", @quote.int(42))
  .render()
println(code)
output
///|
fn answer() -> Int {
  42
}
03 — moonast/gen + cli

Generate files

A generator takes every declaration of its inputs and gives back the code to write. render puts a one-line header above it, so the same inputs always give the same bytes.

async fn main {
  @cli.run(Describe::{}, @env.args()[1:])
}

One chain

From an annotation to a file

Five steps, each one a call you can make on its own. This is what a dev_build rule runs on every build.

1

The declaration is annotated

#demo.describe sits above pub struct Point. Nothing else about the struct has to change.

2

gen reads it

@gen.read gives every declaration of the input files as a Decl, in source order.

3

attr binds the annotation

@attr.find locates it, and a Spec turns its payload into typed arguments — or refuses, with the line and column.

4

quote fills a template

@quote.items(...).set(...).render() gives a Code, one per annotated declaration, joined into one.

5

cli writes the file

@cli.run writes it, or with --check compares it and refuses when it is stale.

the generator
struct Describe {}

impl @gen.Generator for Describe with fn name(_) {
  "describe"
}

impl @gen.Generator for Describe with fn generate(_, decls) {
  let out = []
  for decl in decls {
    guard decl is Struct(name~, fields~, attrs~, ..) &&
      @attr.find(attrs, "demo.describe") is Some(_) else {
      continue
    }
    let text = name + "(" + fields.map(f => f.name).join(", ") + ")"
    let source =
      #|fn $T::describe(self : $T) -> String {
      #|  ignore(self)
      #|  $text
      #|}
    out.push(
      @quote.items(source)
      .set("T", @quote.ident(name))
      .set("text", @quote.string(text))
      .render(),
    )
  }
  @quote.join(out)
}
Twenty-six lines, and Point::describe now exists. The full walkthrough — including the build rule and --check — is in the guide.
What you get

Four packages, one job each

$

Real MoonBit

A template is parsed, not assembled from strings. Escaping and layout are the official ones.

#

Typed arguments

Declare what an annotation takes once, then read strings, names, booleans and types by key.

↹

Deterministic output

One header, one body, the same bytes for the same inputs — so a stale file is a diff you can fail on.

⌗

Positions in refusals

Every refusal carries the line and column of what was wrong, not a stack trace.

PackageWhat it holds
moonast/quoteTemplates: real MoonBit with $holes, filled by replacing nodes and printed by the official formatter.
moonast/attrAnnotations as typed arguments: find #lib.name(...) and bind its arguments against a spec.
moonast/genDeclarations read into plain views, the Generator trait, and render, which gives the file.
moonast/clirun: the whole main of a generator binary. Native and wasm.
